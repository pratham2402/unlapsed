# Unlapsed

MIT licensed. Built for the Nebius x NVIDIA Global AI Hackathon.

Live demo: <https://unlapsed.onrender.com>

Demo video: <https://youtu.be/lKTBVr9TERI>

Unlapsed is a private renewal agent for the documents that decide whether you can travel, drive, work, or stay covered. It watches expiry dates first. When you add a dated event, it reads the event, infers whether it is domestic or international, checks the current official requirement, builds a dependency-aware plan backward from the date, marks what blocks the event and what is a parallel risk, and prepares the packet.

Track: **Personal AI**.

## The problem

A passport, a visa, a driver's license, an insurance policy, and a professional license all expire on different schedules. The hard part is not remembering one date. It is the chain: a passport must be renewed before a visa application, the visa must be approved before a trip, and a professional license may need continuing education hours before it can be renewed.

Most tools stop at a reminder. Unlapsed plans the chain, checks the current rule on the official source, and prepares the paperwork.

## What it does

- Watches expiry dates and shows the nearest expiry first.
- Reads text-based PDFs with `pypdf` and extracts the type, issuer, holder, issue date, expiry date, and constraints.
- Stores every extracted fact with its source page, exact source line, and confidence.
- Infers the event style, destination country, and relevant documents from the event text, home location, and document inventory. The user can override the reading.
- Searches the official issuer site with Tavily and extracts the current fee, processing time, required documents, and steps.
- Verifies the destination's passport validity rule and visa requirement from an official source. The planner uses the verified number of months, not a fixed six-month assumption.
- Adds a generic visa verification task for non-India destinations when the official source says a visa is required or leaves the requirement unstated. The India e-Visa keeps its detailed task.
- Refuses to guess. If no official source is found, the requirement is marked `needs_manual_check`.
- Builds an event-aware dependency graph. An international trip chains the passport renewal, the visa, and the final travel check. Domestic travel makes the driver's license the blocking document. A move, a job start, and a generic dated event use their own relevance rules.
- Plans backward from the event date and compares standard versus expedited processing.
- Falls back to a true expiry watch when no event exists. It does not invent a trip or a default departure date.
- Separates event blockers from parallel risks. It does not estimate trip losses or other personal costs.
- Generates a PDF packet with the checklist, evidence citations, form-ready data, and per-document cover letters.
- Generates an `.ics` calendar file.
- Runs on a schedule and records every change in an activity log.

## The demo scenario

The seeded case is a synthetic US professional with four generated, text-based documents and a trip to India from 10 to 24 January 2027. The PDFs are fictional and are generated by `scripts/generate_sample_pdfs.py`. They are not real identities and they are not scans.

- The home location is inferred as the United States from the passport issuer.
- The destination country is India, and the agent reads the event as an international trip.
- The passport expires on 14 June 2027.
- The agent checks the destination's passport validity rule and visa requirement on `travel.state.gov`. The seeded demo can show six months; if the source cannot be verified, the planner does not assume a period. It adds a blocking manual verification task.
- India requires six months of passport validity beyond the return date, so the passport must be valid through 24 July 2027.
- The current official processing time is 4 to 6 weeks routine, so the standard renewal starts on 7 November 2026 and is due on 19 December 2026.
- The agent then schedules the e-Visa and the final travel check.
- The renters policy expires on 1 January 2027, before departure, so it is a parallel risk.
- The professional license expires on 31 March 2027 and needs 30 continuing education hours, so it is a second parallel risk.

With a verified six-month rule, the plan has four blocking tasks and two parallel risks. Without a verified rule, it adds a blocking manual verification task instead of assuming a period. The official renewal fees are shown in the evidence table. The app does not estimate trip losses or other personal costs.

## Why this is not another expiry tracker

The category has many trackers. The difference is the combination:

1. **Documents first, events second.** The home screen is the expiry watch. The event plan is a mode you enter when a date creates a chain.
2. **A chain, not a list.** The plan knows that the e-Visa depends on the new passport, that a domestic trip depends on a valid driver's license, and that the final check depends on the chain.
3. **Evidence, not answers.** Every fee, processing time, required document, and passport validity rule is tied to an official source with a checked date. The UI shows the source and the confidence.
4. **A packet, not a reminder.** The agent assembles the checklist, form-ready data, per-document cover letters, and calendar events.
5. **A visible refusal to guess.** Weak or missing evidence becomes `needs_manual_check`, not a fabricated deadline.
6. **A usable no-event mode.** With no dated event, it watches expiry windows. It does not pretend a trip exists.

The dates and dependency rules are deterministic code. The models extract fields, read official pages, and write explanations. The model does not decide the legal deadline.

## Architecture

```text
PDF bytes
  -> pypdf text extraction
  -> Nemotron extraction (JSON)
  -> facts with page, excerpt, confidence
                                  |
Event text + destination + destination country + home location + document inventory
  -> Nemotron event analysis (type, domestic/international, relevant docs)
  -> deterministic event rules -> plan tasks -> blocker labels
                                  |
Tavily -> official source -> Nemotron verification (fees, passport validity, visa)
  -> evidence + citations
                                  |
                     PDF packet + ICS calendar + activity log
```

### Nebius Token Factory and NVIDIA Nemotron

- The OpenAI-compatible Token Factory endpoint is used for every model call.
- `NEBIUS_MODEL_FAST` handles document extraction. The default is a Nemotron Nano class model.
- `NEBIUS_MODEL_REASONING` handles official-source extraction and longer explanations. The default is a Nemotron Super class model.
- Model IDs change. Run `uv run python scripts/list_models.py` after adding your key and update `.env` if needed.
- The app works without a key in sample mode, using the deterministic extractor and labelled sample requirements. Live mode is the intended demo.

### Tavily

Tavily is the evidence layer. The app searches an allowlist of official domains, such as `travel.state.gov`, `indianvisaonline.gov.in`, `dmv.ca.gov`, and `bpelsg.ca.gov`. The result is stored with its URL, title, excerpt, checked time, and confidence. If no official result is found, the requirement is marked for manual verification.

### Agent and deterministic core

The model does the language work. Code owns the consequences.

| Step | Who does it |
|---|---|
| Read the PDF text | deterministic `pypdf` |
| Extract dates, holder, issuer, document type | model, with a rules fallback |
| Read the event and infer domestic or international | model, with a rules fallback and an optional user override |
| Decide which documents can affect the event | model suggestion, checked against the document inventory and expiry dates |
| Search official sources | deterministic query plus Tavily |
| Extract fee, processing time, required documents | model reads the official results |
| Extract the destination's passport validity rule | model reads the official result |
| Decide the dates and dependency order | deterministic code |

The extraction and event-classification fallbacks are intentional. They keep the demo usable without keys and give the model a bounded failure mode. Legal rules are different: if an official validity or visa rule is missing, the app adds a manual verification task instead of assuming a period.

What stays hardcoded, and why:

- **Official-source allowlists.** The model may choose a URL only from supplied official hits. It cannot invent a source.
- **Date arithmetic and deadline comparison.** The model can supply the rule and the citation. The code applies it.
- **Dependency order and task structure.** The model can say which documents matter. The code decides what must happen before what.
- **Risk pricing assumptions.** They are labelled planning assumptions, not quotes.
- **Safety controls.** Upload limits, PDF-only input, read-only demo guards, and path handling are not model decisions.
- **Data contracts.** Document types, status values, and the shape of a requirement are stable so the UI and packet can trust them.

### Framework and tools

There is no LangChain or LangGraph. The orchestration is a small Python service layer around the OpenAI-compatible Nebius client and the Tavily Python client. LangSmith tracing is optional. The tools are plain function calls, not MCP servers. That keeps the runtime small and the failure modes visible.

### Persistent memory

The SQLite database stores:

- documents and their extracted fields
- facts with provenance
- official requirements and their check history
- destination travel rules with their source and check history
- events, plans, tasks, packets, agent runs, and activities

The agent plans from the stored facts and requirements. It does not re-read the PDF on every run.

### Cost and model use

- Page loads make no model calls. The plan, evidence, and activity log are read from SQLite.
- A full run makes one event-analysis call, one extraction call per new document, one travel-rule and visa call for an international event, and one policy extraction call per relevant document type. An upload triggers a full check because a new document can change the chain.
- An explicit plan-style override with a known home location skips the event-analysis model call.
- Requirements and travel rules are cached. The overnight run refreshes them once, not on every page load.
- Tavily searches are limited to official domains and stored with the requirement.
- The planner, the date math, and the blocker labels are deterministic. They do not spend tokens.
- The fast model handles document extraction and event analysis. The reasoning model handles official-policy extraction and the travel rule. If the reasoning call fails, the app retries once with the fast model, then falls back to a source-only result.

### Always-on behavior

`scripts/overnight_run.py` runs the same agent without a browser. A cron entry can make the assistant check for changes every morning:

```cron
0 7 * * * cd /path/to/unlapsed && uv run python scripts/overnight_run.py >> data/overnight.log 2>&1
```

Every run writes to the activity log, so a change in processing time, fee, or source is visible after the fact.

### Privacy

Uploaded PDFs are read in memory and are not written to disk in the demo. Only structured fields and source excerpts are stored. The privacy page supports export and deletion.

## Quickstart

Requirements: Python 3.13 and [uv](https://docs.astral.sh/uv/).

```bash
cd unlapsed
uv sync
cp .env.example .env
# paste your keys into .env
uv run python scripts/check_keys.py
uv run python scripts/list_models.py
uv run python scripts/seed_demo.py
uv run uvicorn app.main:app --reload
```

Open <http://127.0.0.1:8000>.

If `NEBIUS_API_KEY` or `TAVILY_API_KEY` is missing, the app still runs. The rail shows **Sample data** and the evidence is labelled `fallback` or `needs manual check`.

## Deploy

The repo includes a `Dockerfile`, `start.sh`, and `render.yaml`.

### Render

[Deploy to Render](https://render.com/deploy?repo=https://github.com/pratham2402/unlapsed)

1. Push the repository to GitHub.
2. In Render, create a new Web Service from the repository. Render reads `render.yaml`.
3. Add `NEBIUS_API_KEY` and `TAVILY_API_KEY` as secret environment variables.
4. Deploy. The first boot runs `scripts/bootstrap.py`, which seeds the demo only when the database is empty.

The free plan uses an ephemeral disk. The SQLite file is generated state and is ignored by git. On a cold start, `scripts/bootstrap.py` creates the database and seeds it from the tracked sample PDFs. With no keys, it uses deterministic extraction and labelled fallback requirements. The public demo runs with `DEMO_READ_ONLY=true`, which blocks uploads, event creation, agent runs, and deletes. This keeps a public URL from spending the sponsor credits. Run locally with your own keys to use the full interactive path.

For a persistent deployment, attach a disk to `/app/data` or set `DATABASE_URL` to a Postgres database. The additive SQLite migration does not alter an existing Postgres schema, so use a real migration tool there.

### Docker

```bash
docker build -t unlapsed .
docker run -p 8000:8000 --env-file .env unlapsed
```

`.env` is excluded from the image by `.dockerignore`. Pass it at runtime.

The shot-by-shot recording script, including the voiceover lines and the on-screen actions, is in [VIDEO_SCRIPT.md](VIDEO_SCRIPT.md).

## Limitations

- The demo uses one seeded user and has no login. Add authentication before a real deployment.
- The demo uses clean, text-based PDFs. Scanned documents are rejected with a clear message. OCR is the next step.
- The event classifier is a model suggestion with a deterministic fallback. It can misread an event. The plan page shows the reading, the home location, and the confidence, and the event form has an optional plan-style override.
- The planner covers international trip, domestic travel, move, job start, and other dated event. It also covers a no-event expiry watch. The model can suggest relevant documents, but the code still owns the dependency rules and dates. A new event style needs new rules and tests.
- The travel-rule source registry is US-focused. A non-US home location is marked for manual verification.
- Visa processing is detailed for India only. Other international destinations get a generic visa verification task from the official travel page, not a country-specific application workflow.
- Destination country is optional. If it is omitted and the model is unavailable, a city or region destination can be classified conservatively. The form lets the user correct the country, and the plan shows the reading.
- The additive migration is SQLite-only. A production Postgres deployment needs a real migration tool.
- The official-source allowlist is US-focused and demo-focused. A production version needs a source registry per document type and jurisdiction.
- The app does not file forms or move money. It prepares the packet and the calendar; the user reviews and submits.
- The model can still read a page incorrectly. That is why every fact has a source excerpt and a confidence score.
- This is not legal advice.
